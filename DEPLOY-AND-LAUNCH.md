# Деплой і запуск лендінга: runbook

> Призначення: повний перевірений шлях від коду до працюючого лендінга **всередині продукту** —
> деплой-пайплайн, налаштування Vercel, порядок запуску iframe-інтеграції і таблиця розв'язань
> усіх реальних інцидентів. **Все в цьому документі — Спостережено** на запуску першого лендінга
> (кожен пункт — фактичний інцидент або рішення, що спрацювало).

---

## 1. Стандартний деплой-флоу: git → Vercel (єдиний рекомендований)

```
код → git push (секунди) → GitHub → Vercel Git Integration → авто-білд → прод
```

**Спостережено, чому саме так:** передача коду інлайном через AI-агента (MCP-інструмент деплою)
вимагає одного безперервного ~3-хвилинного виклику на кожен деплой — шість спроб поспіль обірвано
помилкою API `529 Overloaded`. Git-push — коротка команда, рветься нема чому; бонуси: історія,
відкат у два кліки у Vercel UI, preview-деплої на гілки, деплоїть будь-хто без AI-каналу.

Налаштування (один раз на лендінг):
1. `git init` → GitHub-репо → push `main`.
2. Vercel: проєкт → Settings → Git → Connect Git Repository → `main`.
3. Далі кожен `git push` = продакшн-деплой; фікс типової помилки білда займає ~3 хвилини end-to-end.

## 2. Налаштування Vercel-проєкту (мультилендінговий патерн)

Один проєкт (напр. `catbet`) — багато лендінгів у підпапках: `домен/<landing-name>/`.

| Параметр | Значення | Чому (Спостережено) |
|---|---|---|
| `buildCommand` | `npm run vercel-build` | **ліміт 256 символів** у Vercel API — довгий ланцюжок падає з `Invalid request`; весь ланцюжок живе в package.json |
| package.json `vercel-build` | `NUXT_APP_BASE_URL=/<landing>/ NITRO_PRESET=static nuxt generate && node scripts/compose-outdir.mjs` | **без `NITRO_PRESET=static` Nitro на Vercel автообирає vercel-preset** → вихід у `.vercel/output/`, compose падає з `ENOENT .output/public`, а Build Output API перекриває outputDirectory |
| `outputDirectory` | `outdir` | compose-скрипт складає: `outdir/<landing>/` + кореневий `index.html`-каталог + `test-parent.html` |
| `framework` | `null` | білд повністю керується скриптом |
| compose-скрипт | node (`scripts/compose-outdir.mjs`), НЕ sed | кросплатформенність; тут же: фікс `url(/_fonts/` → префікс (quirk @nuxt/fonts із baseURL), прибирання dev-файлів, `rm -rf .vercel` |

## 3. Асети: CDN-адреси закріплені в сорсі

- Медіа (зображення/відео) живуть на CDN; **URL-и прописані прямо в коді** → код у репо == код у проді,
  без трансформацій між ними. `public/img`/`public/video` — у `.gitignore`.
- **Перед кожним push:** `git grep -nE '"/img/|/video/'` по репо = 0 збігів (поза CDN-URL).
  **Спостережено:** три пропущені локальні шляхи (декор одного блоку) поклали git-білд —
  Vite **падає на етапі збірки** з `Rollup failed to resolve import "/img/..."`, якщо файлів немає.

## 4. Гігієна репозиторію

- **Жодних приватних submodules** у репо лендінга — Vercel не може їх клонувати, git-білд падає.
  Методологію тримати локальною копією поза індексом лендінг-репо (або зробити її репо публічним).
- `.gitignore`: `node_modules/`, `.nuxt/`, `.output/`, `outdir/`, медіа.

## 5. Біллінг Vercel (Спостережено на реальному рахунку)

- **НЕ деплоїти лендінг як SSR-сервер**: сорс-деплой з авто-детектом Nuxt = функції + ISR — старий
  тестовий проєкт спалив $9.20 ISR Writes + CPU/Observability за дні, наближаючи spend cap ($20) —
  при його досягненні Vercel паузить УСІ проєкти команди.
- Статична збірка (розділи 1–2) коштує ~нічого (`x-vercel-cache: HIT`, нуль функцій, медіа на CDN).
- Застарілі server-проєкти **видаляти**, не лишати висіти.

## 6. Порядок запуску iframe-інтеграції (найважливіший розділ)

**Спостережено: блокер №1 запуску — origin whitelist, а не код.** Продукт вбудовував лендінг ідеально
за контрактом з першої спроби; «не працює» означало лише те, що origin стейджа продукту не був у
whitelist ядра — воно **мовчки** не шле `loaded`/`height`, iframe лишається ~150px.

Послідовність запуску:

1. **ДО першого тесту фронтів** — зібрати повний перелік origin-ів продукту (prod / stage / dev,
   точні схеми й піддомени) і додати в `IframeBridge.init({ allowedParentOrigins })`. Це питання
   Discovery-фази; без нього перший тест гарантовано «не працює».
2. Задеплоїти **hosted test-parent** (`/test-parent.html` на домені лендінгів; його origin — у
   whitelist) — єдиний спосіб показати робочий embed без стенда продукту і головний інструмент
   діагностики (лог loaded/height/event_action/token, перемикач auth).
3. Верифікація на стейджі продукту (порядок перевірок):
   - знайти `<iframe>` і прочитати його **`src`** — чи всі контрактні query-параметри на місці
     (`auth`, `locale`, `theme`, `parentOrigin`) і який саме origin передано;
   - висота фрейма: росте до висоти контенту = канал живий; ~150px/статична = канал мертвий;
   - консоль **самого iframe** (right-click усередині → Inspect): діагностичний warning
     `[iframe-bridge] embedded without connected channel; parentOrigin = …` називає точну причину.
4. Після першого успішного embed — підняти iframe-розділи методології з `Рекомендовано` до
   `Спостережено` (зроблено у v1.6.0).

## 7. Таблиця інцидентів: симптом → причина → фікс

| Симптом | Причина | Фікс |
|---|---|---|
| Iframe ~150px, «не тягнеться», без помилок | origin батька не у whitelist ядра → тихий no-op | додати origin у `init({ allowedParentOrigins })`; перевірити консоль iframe |
| `Invalid request: buildCommand ≤ 256 characters` | довгий ланцюжок у projectSettings | ланцюжок → `package.json` script, buildCommand = `npm run vercel-build` |
| `ENOENT .output/public` у білді на Vercel | Nitro автообрав vercel-preset | `NITRO_PRESET=static` у vercel-build |
| `Rollup failed to resolve import "/img/…"` | локальний медіа-шлях у коді, файл поза репо | `git grep '"/img/'` → замінити на CDN-URL |
| Git-білд падає на клонуванні | приватний submodule у репо | прибрати gitlink/`.gitmodules` або зробити публічним |
| Шрифти 404 з `/_fonts/` при baseURL-підпапці | quirk @nuxt/fonts: частина `@font-face` ігнорує baseURL | префікс-фікс у compose-скрипті + перевірка `grep 'url(/_fonts/'` = 0 |
| Деплой через AI-агента рветься (529) | довга інлайн-передача через API | git-флоу (розділ 1) |
| Кредит Vercel тане без трафіку | старий SSR/ISR-проєкт платить за кожен перегляд | видалити; лендінги — тільки статикою |
| Dev-сервер 500 `#app-manifest` після generate | побитий `.nuxt`/Vite dep-кеш | `rm -rf .nuxt node_modules/.vite` + рестарт |
| «Лендінг на проді не той/старий» | білд не пройшов, live лишився попередній | перевіряти маркер нового білда (новий файл/чанк-хеш), не вигляд |

## 8. Чекліст запуску (go-live gate)

- [ ] Git-репо підключено до Vercel; тестовий push → авто-білд проходить.
- [ ] `git grep '"/img/\|/video/'` = 0; медіа на CDN; білд-маркер нового деплою перевірено.
- [ ] Origin-и продукту (prod/stage) у whitelist; hosted test-parent live і показує loaded/height.
- [ ] На стейджі продукту: iframe отримує висоту, CTA шлють `event_action`, локаль перемикається.
- [ ] Застарілі server-проєкти видалені; spend cap не на межі.
